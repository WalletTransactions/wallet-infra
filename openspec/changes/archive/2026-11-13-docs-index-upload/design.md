# Design

## Context

Скрипты контура лежат в `infra/env/*.sh` и запускаются либо вручную на хосте, либо из
Jenkins через `BuildPlatform/jobs/lib/env_run.sh <env> <скрипт.sh>` (имя `^[a-z-]+\.sh$`).
Контейнер Jenkins видит рабочую папку организации по пути `WALLET_TRANSACTIONS_PATH`, каталог
состояния и секреты. `wallet-docs` принимает `PUT /docs/index/{repo}` по `X-Index-Token`,
внутри сети контура, мимо гейтвея (change `docs-service`). `INDEX_TOKEN` лежит в
`wallet-docs.env` контура. См. proposal.md.

## Goals / Non-Goals

**Goals:**
- Один скрипт, который заливает один или все репозитории; безопасен без wallet-docs.
- Токен не светится нигде, кроме контейнера, которому он принадлежит.

**Non-Goals:**
- Заливка по событию «слит PR»: достаточно ночного запуска и ручного.
- Клонирование репозиториев из GitHub: берём рабочую папку организации на хосте.

## Decisions

**D1. Источник — рабочая папка, а не git-клон.** Jenkins уже монтирует
`WALLET_TRANSACTIONS_PATH`; токена на чтение 11 репозиториев нет (токен выдан только на
`wallet-infra`). Обратная сторона: в индекс попадают незакоммиченные черновики, но
админу виден вид `change`, а пользователям доступны только `specs/` (по требованию
сервиса), которые меняются лишь при архивации. Приемлемо; при необходимости позже
переходим на `git archive` отдельным change'ем.

**D2. Запрос внутри контейнера.** `docker exec -i <wallet-docs> sh -c 'curl … -H
"X-Index-Token: $INDEX_TOKEN" --data-binary @- …'`, тело — со стандартного входа. Образ
`wallet-docs` уже содержит `curl` ради healthcheck. Токен остаётся в окружении
контейнера, как пароль `wallet_reader` в `migrate.sh`. Альтернатива «читать токен из
файла секретов и передавать curl'ом с хоста» отвергнута: токен прошёл бы через процесс
Jenkins и его журнал.

**D3. Сборка JSON через `jq`, иначе `python3 -I`.** Нужно экранировать содержимое файлов;
shell-конкатенация хрупка. Какая из утилит есть в окружении, проверяет задача 1.1.

**D4. Только `*.md` из `openspec/`, без симлинков.** Файлы читаются `find -type f`, пути
отдаются относительно репозитория; всё остальное (код, `.env`, сборки) не открывается.

**D5. Мягкий отказ.** Нет профиля, контейнера или ответ не 2xx → предупреждение и код 0, при
`all` продолжаем. `--strict` для ручной проверки и CI. Job превращает предупреждение в
`UNSTABLE`: по цвету видно, что залить не вышло, но остальное не страдает.

**D6. Блокировка контура.** `env_lock`, как у остальных скриптов: заливка не идёт
параллельно с выкатом и миграцией. Заливка может быть долгой при первом запуске (эмбеддинги),
поэтому job имеет таймаут 60 минут и запрещает параллельные сборки.

**D7. Ночной запуск.** `H 3 * * *` для test; prod — тем же job'ом по параметру `ENV`, по
расписанию только test до проверки качества.

**Правки вне wallet-infra:** BuildPlatform (`jobs/docs-index/Jenkinsfile`; каталог вне git —
сделать копию перед правкой); wallet-docs (контракт `PUT /docs/index/{repo}`, поле
`skipped`).

## Risks / Trade-offs

- [Черновики из рабочей папки в индексе админа] → вид `change` виден только админу; спеки
  пользователей меняются только архивом.
- [Репозитория нет на диске] → пропуск с пометкой, не ошибка.
- [Тело запроса до 16 МБ через stdin `docker exec`] → самый большой репозиторий ~1 МБ;
  лимит сервиса 16 МБ, при превышении `413` с понятным предупреждением.
- [Утечка токена через `set -x`] → скрипт не включает трассировку, а README запрещает; задача
  1.3 проверяет вывод и список процессов.
- [Jenkins-каталог вне git] → резервная копия `jobs/` перед правкой, как для других job'ов.
