# Proposal

## Why

В режимах `internal` и `tailscale` (адреса не `.ts.net`) сертификаты подписывает
собственный CA контура. По `add-tls-ingress` (design D1) его создаёт сам Caddy при
первом запуске и хранит в томе `wallet-<env>_tls-data`. У этого два недостатка:

- корень пропадает вместе с томом (`down -v`, `volume prune`, переезд на другой хост).
  Тогда Caddy молча создаёт новый корень, и все телефоны и ПК перестают доверять
  серверу. Android показывает «Trust anchor for certification path not found», и
  корень приходится переустанавливать на каждом устройстве. В резервную копию
  секретов корень не попадает;
- получить корень можно только на хосте (`export-ca.sh` через `docker compose exec`).
  Скачать его с самого сервера нельзя.

CA для mTLS (`add-internal-mtls`) уже живёт в секретах контура (`mtls-ca/`). CA
входа устроен по-другому без причины.

## What Changes

- Корень CA входа хранится в секретах контура: `<secrets>/tls-ca/root.crt` и
  `root.key` (600). Caddy берёт его через `pki { ca local { root … } } }` и сам
  выпускает от него промежуточный сертификат (в томе) и сертификаты сайтов.
- Новый скрипт `infra/env/tls-ca-init.sh <env>` (один раз на хосте). Если в томе
  уже есть CA Caddy, переносит **тот же** корень, и установленные на устройства корни
  остаются годными. Если CA нет, создаёт новый корень (EC P-256, 10 лет).
- Прокси отдаёт публичный корень по `https://<адрес>:<порт>/ca.crt` на каждом адресе
  контура. Удобнее всего скачивать по имени `.ts.net`: у него сертификат Let's Encrypt,
  поэтому подлинность скачанного корня подтверждена без установки чего-либо.
- `export-ca.sh` читает корень из секретов, а пока его там нет — из тома.
- Пока корень не перенесён, контур работает как раньше (CA в томе), а
  `up.sh` / выкат предупреждают, что корень нужно перенести. Выкат не ломается.
- Проверки при запуске: оба файла есть, ключ 600 и подходит к сертификату, это CA,
  срок больше года.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `tls-ingress`: «Режимы сертификата» — корень CA в секретах; «Корень CA для
  устройств» — `tls-ca-init.sh`, `/ca.crt`, ключ не покидает секреты.

## Impact

- `infra/env/tls.sh`, `infra/env/tls-ca-init.sh` (новый), `infra/env/export-ca.sh`,
  `compose.yaml` (два монтирования `tls-proxy`), `infra/env/README.md`.
- Вне wallet-infra: ничего обязательного. Ссылка на `/ca.crt` в справке wallet-web и
  на экране ошибки сертификата в android-wallet (`explain-network-errors`) — отдельно.
