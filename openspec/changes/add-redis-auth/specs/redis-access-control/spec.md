# Spec Delta

## Purpose

Аутентификация и минимальные права доступа к Redis контура, где лежат активные токены пользователей: чужой контейнер в сети не может читать, подделывать или отзывать токены, а штатные сервисы и оператор продолжают работать.

## ADDED Requirements

### Requirement: Redis требует аутентификацию
Redis контура SHALL выполнять команды только после аутентификации. Безымянный доступ (пользователь `default` без пароля) MUST быть выключен после завершения выката.

#### Scenario: Контейнер без учётных данных
- **WHEN** контейнер сети контура, не имеющий пароля, подключается к Redis и выполняет `GET` или `KEYS *`
- **THEN** Redis отвечает отказом аутентификации и данные не отдаются

#### Scenario: Неверный пароль
- **WHEN** клиент предъявляет неверный пароль существующего пользователя
- **THEN** Redis отказывает и не раскрывает, существует ли пользователь

### Requirement: Отдельный пользователь на назначение с минимальными правами
Каждое назначение SHALL иметь собственного пользователя Redis: сервис google-auth, exporter метрик, healthcheck контейнера и оператор (admin). Права MUST ограничиваться командами и префиксами ключей, которые нужны назначению. Пользователь google-auth MUST NOT иметь прав на `FLUSHALL`, `FLUSHDB`, `CONFIG`, `KEYS` и на ключи вне префиксов токенов, кодов привязки и счётчиков входа.

#### Scenario: google-auth вне своих ключей
- **WHEN** google-auth под своим пользователем пытается прочитать ключ вне своих префиксов или выполнить `FLUSHALL`
- **THEN** Redis отказывает по ACL и отказ попадает в журнал ACL

#### Scenario: Healthcheck
- **WHEN** healthcheck выполняется под пользователем `health`
- **THEN** `PING` проходит, а `GET` любого ключа отклоняется

#### Scenario: Exporter
- **WHEN** redis-exporter подключается под своим пользователем
- **THEN** метрики Redis собираются, а чтение значений токенов недоступно

#### Scenario: Оператор
- **WHEN** оператор подключается под `admin` через `docker exec`
- **THEN** ему доступны все команды, в том числе `FLUSHALL` для `test-refresh.sh`

### Requirement: Учётные данные контура изолированы и скрыты
Пароли пользователей Redis SHALL генерироваться случайно, быть разными у каждого пользователя и у каждого контура и храниться в секретах контура вне git. В ACL-файле, смонтированном в Redis, MUST храниться только хеш пароля. Значения паролей MUST NOT попадать в журналы выката, в вывод скриптов и в переменные окружения, видимые `docker inspect` у контейнеров, которым они не нужны.

#### Scenario: Пароль другого контура
- **WHEN** пароль пользователя Redis контура test предъявляется Redis контура prod
- **THEN** аутентификация не проходит

#### Scenario: Журнал выката
- **WHEN** `up.sh` запускается с включённой защитой Redis
- **THEN** в выводе и в журнале Jenkins нет значений паролей

#### Scenario: ACL-файл
- **WHEN** просматривается ACL-файл контура
- **THEN** в нём нет паролей в открытом виде

### Requirement: Токены пользователей не теряются при включении
Включение защиты MUST NOT удалять и менять сохранённые токены. После выката активные access-, refresh- и MCP-токены, коды привязки Telegram и счётчики входа SHALL оставаться в Redis, а пользователи SHALL оставаться залогиненными.

#### Scenario: Сессии после включения
- **WHEN** защита включена на контуре с активными сессиями
- **THEN** число ключей токенов в Redis до и после совпадает, пользователь продолжает работать без повторного входа

#### Scenario: Refresh после включения
- **WHEN** клиент обновляет access-токен через refresh-токен, выданный до включения защиты
- **THEN** обновление проходит, refresh-токен ротируется как обычно

### Requirement: Включение без простоя входа
Порядок включения SHALL позволять переключать клиентов Redis по одному: пользователь `default` остаётся доступным, пока все штатные клиенты не перейдут на собственных пользователей, и выключается отдельным последним шагом. Единственное допустимое прерывание — рестарт контейнера Redis, после которого google-auth пересоздаётся.

#### Scenario: Пока клиенты не переехали
- **WHEN** выполнен шаг «Redis с ACL, `default` включён»
- **THEN** старая версия google-auth продолжает работать без пароля

#### Scenario: Остался клиент на `default`
- **WHEN** перед выключением `default` в списке клиентов Redis есть соединение пользователя `default`
- **THEN** выключение не выполняется, и выкат сообщает, чьё это соединение

#### Scenario: Все клиенты переехали
- **WHEN** в списке клиентов Redis нет соединений пользователя `default`
- **THEN** `default` выключается без остановки входа и обновления токенов

### Requirement: Откат без потери данных
Откат защиты на любом шаге SHALL возвращать Redis к предыдущему ACL-файлу без потери данных и без перевыпуска токенов пользователей.

#### Scenario: Возврат безымянного доступа
- **WHEN** на test возвращают предыдущий ACL-файл с включённым `default`
- **THEN** сервисы работают как до включения защиты, токены на месте

### Requirement: Поведение google-auth при неверных учётных данных
google-auth SHALL при старте с неверным пользователем или паролем Redis не запускаться и записывать в журнал понятную причину без значения пароля. Сервис MUST NOT работать с деградацией, принимая входы без хранилища токенов.

#### Scenario: Неверный пароль на старте
- **WHEN** google-auth стартует с неверным `REDIS_PASSWORD`
- **THEN** процесс завершается с ошибкой, в журнале «Redis: AUTH не прошёл» без пароля, healthcheck контейнера показывает неисправность

#### Scenario: Прежняя настройка
- **WHEN** google-auth стартует без `REDIS_USERNAME`
- **THEN** он выполняет `AUTH <пароль>` как раньше, и поведение не меняется

### Requirement: Метрики и healthcheck не теряются
При включённой защите метрики Redis контура SHALL по-прежнему попадать в Prometheus с меткой `env`, а healthcheck контейнера Redis — проходить без доступа к значениям ключей.

#### Scenario: Метрики Redis
- **WHEN** защита включена на test
- **THEN** цель `redis-exporter` в состоянии up, метрики `redis_connected_clients` и `redis_memory_used_bytes` обновляются

#### Scenario: Недоступный exporter
- **WHEN** учётные данные exporter неверны
- **THEN** цель в состоянии down, а сервисы и вход пользователей не затронуты

### Requirement: Доступ оператора и служебных скриптов
Скрипты стенда (`test-refresh.sh`) и инструкции оператора SHALL использовать пользователя `admin` и передавать пароль без вывода в журнал. Инструкции в README MUST показывать подключение `docker exec … redis-cli` с аутентификацией.

#### Scenario: Обновление test из prod
- **WHEN** выполняется `test-refresh.sh`
- **THEN** `FLUSHALL` на Redis test проходит под `admin`, а пароль не печатается

#### Scenario: Подключение оператора
- **WHEN** оператор выполняет команду из README для подключения к Redis контура
- **THEN** подключение проходит и показывает список ключей токенов
