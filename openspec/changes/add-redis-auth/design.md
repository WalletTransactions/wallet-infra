# Design

## Context

Мотивация и объём — в `proposal.md`, требования — в `specs/redis-access-control/`. Что есть сейчас (проверено по коду и `compose.yaml`):

- Redis: `redis:7-alpine`, `redis-server --appendonly yes`, том `redis-data`, без пароля, порт не публикуется; healthcheck `redis-cli ping`. Нужен только google-auth: wallet-ai и wallet-telegram Redis не используют (в их исходниках только комментарии).
- Клиент google-auth — свой, на голом RESP (`redis_client.cpp`), одно постоянное соединение и мьютекс. Умеет только `AUTH <пароль>` (пользователь `default`), настройки `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`. **Переподключения нет**: после рестарта Redis сокет мёртв, пока не перезапущен сам google-auth. При неверных учётных данных на старте сервис пишет ошибку и завершается (`return 1`).
- Команды клиента: `SET` (с `EX`, `EXAT`, `XX`), `GET`, `GETDEL`, `DEL`, `EXISTS`, `SADD`, `SREM`, `SMEMBERS`, `EXPIRE`, `EXPIRETIME`, `INCR`, `TTL`.
- Префиксы ключей: `refresh_token:`, `access_token:`, `user_refresh_tokens:`, `user_access_tokens:`, `mcp_token:`, `user_mcp_tokens:`, `tg_link_code:`, `authfail:email:`, `authfail:ip:`.
- Другие потребители Redis: redis-exporter (`infra/monitoring/compose.yaml`, `REDIS_ADDR` без пароля), `test-refresh.sh` (`redis-cli FLUSHALL`), оператор (`docker exec … redis-cli`, README).
- Секреты контура — `~/.config/wallet-secrets/<env>/`; сгенерированное — `~/.local/state/wallet-envs/<env>/generated/` (права 0644, поэтому секретов там нет). Стек метрик читает пароли из секретов контура и подставляет их с префиксом `PROD_`/`TEST_` (`infra/monitoring/up.sh`).
- Лимиты памяти: Redis 64 МБ, google-auth 64 МБ; ACL памяти почти не добавляет.

## Goals / Non-Goals

**Goals:**
- Безымянный доступ к Redis закрыт; права штатных потребителей минимальны.
- Выкат без потери токенов и без остановки входа дольше одного рестарта Redis; откат на любом шаге.
- Пароли не попадают в git, журналы и чужие контейнеры.

**Non-Goals:**
- TLS до Redis (`add-internal-mtls`, группа 9): пароль защищает от доступа без учётных данных, но не от перехвата в сети, пока нет TLS.
- Переподключение и пул соединений в google-auth (существующая хрупкость, отдельная задача).
- Смена формата ключей и значений токенов; хранение токенов хешами.
- Кластер, Sentinel, внешний менеджер секретов.

## Decisions

### D1. ACL-пользователи, а не один `requirepass`

`requirepass` — один пароль на пользователя `default` со всеми правами: любой клиент, знающий его, может всё. Он же заставляет переключать клиентов одновременно: у клиента с паролем против Redis без пароля `AUTH` вернёт ошибку, и google-auth не стартует. ACL даёт отдельного пользователя на назначение, права по командам и префиксам ключей, пароли в виде хеша и возможность оставить `default` на время перехода.
Альтернатива — `requirepass` без правок кода google-auth: проще, но с простоем при переключении и без минимальных прав.

### D2. Правка google-auth: `REDIS_USERNAME`

`Client` получает необязательное имя пользователя: `AUTH <пользователь> <пароль>`; пусто — прежнее `AUTH <пароль>`. Правка маленькая, обратно совместимая, выкатывается раньше Redis (шаг 1 выката). Меняются `redis_client.cpp`, `main.cpp`, README, `.env.example` и юнит-тест построения команды.

### D3. Пользователи и права

| Пользователь | Права | Назначение |
|---|---|---|
| `google-auth` | `-@all +set +get +getdel +del +exists +sadd +srem +smembers +expire +expiretime +incr +ttl`, ключи только перечисленных префиксов | сервис |
| `exporter` | `-@all` и только команды чтения статистики, которые вызывает redis-exporter (`+info +ping +client\|list +config\|get +dbsize` …); точный список — по журналу ACL на test | метрики |
| `health` | `-@all +ping`, без ключей | healthcheck |
| `admin` | `~* &* +@all` | оператор, `test-refresh.sh` |
| `default` | на время перехода `nopass ~* +@all`, затем `off` | совместимость |

Список команд google-auth сверяется с клиентом и с реальным набором ключей на prod и test перед выкатом (задача 1.1), а затем проверяется по `ACL LOG` на test (5.3–5.4): любой отказ — недостающее право, а не повод ослаблять ACL.
Ограничение: ACL не защищает от злоумышленника, получившего учётные данные самого google-auth (он законно читает и пишет токены); он защищает от остальных контейнеров и от лишних команд.

Проверено на настоящем Redis 7 (2026-11-21): список команд `exporter` на старте — `info ping client|list config|get dbsize slowlog|len slowlog|get latency|latest memory|usage scan type pttl llen scard zcard hlen xlen strlen` (уточнён по `ACL LOG` на test, задача 4.2: redis_exporter v1.62.0 дополнительно просит `client|setname` и `latency|histogram`, остальное — из списка; с ними отказов нет). В ACL-файле Redis комментарии недопустимы (каждая строка — `user …`), поэтому происхождение файла описано в `infra/env/redis.sh`, а не в самом файле. `redis-cli` внутри контейнера Redis подхватывает `REDISCLI_AUTH` пользователя `health` из его `env_file`: при выключенном `default` оператору нужен явный `--user admin` со своим `REDISCLI_AUTH`.

### D4. Учётные данные: по файлу на потребителя

`infra/env/redis-auth.sh` (вызывается из `up.sh` до старта Redis, повторяем): при отсутствии создаёт `~/.config/wallet-secrets/<env>/redis/` и в нём случайные пароли (32 байта, hex), права 0600:
- `google-auth.env` (`REDIS_USERNAME`, `REDIS_PASSWORD`) — в `env_file` google-auth;
- `health.env` (`REDISCLI_AUTH`) — в `env_file` самого Redis, только пароль health;
- `exporter.env` — читает `infra/monitoring/up.sh` и подставляет в exporter с префиксом контура, как пароль мониторинга Postgres;
- `admin.env` — никуда не монтируется, для оператора и `test-refresh.sh`.
Из паролей строится `generated/redis/users.acl` с хешами (`#<sha256>`), без паролей в открытом виде. Так Redis видит в окружении только пароль `health`, а google-auth — только свой. Значения не печатаются, без `set -x` рядом с секретами.

### D5. ACL-файл монтируется каталогом

Каталог, а не файл: скрипты пишут атомарно (временный файл + `mv`), и одиночный bind-mount файла после замены указывал бы на старый inode. Тот же приём у Caddyfile в `add-tls-ingress`. Новый ACL применяется без рестарта: `ACL LOAD` под `admin`; соединения других пользователей не рвутся, соединения выключенного пользователя закрываются.

### D6. Порядок выката (на каждом контуре)

1. **google-auth с `REDIS_USERNAME`** выкатить (rc → релиз) без изменения настроек: поведение прежнее.
2. **Redis с ACL, `default` включён** (`nopass`): рестарт контейнера Redis (AOF и том сохраняются), затем пересоздание google-auth (нет переподключения). Старые и новые клиенты работают.
3. **Переключение клиентов**: `google-auth.env` с пользователем и паролем, healthcheck, exporter, `test-refresh.sh`. Пересоздать google-auth.
4. **Проверка**: `CLIENT LIST` не содержит соединений `user=default`; `ACL LOG` пуст по отказам штатных клиентов.
5. **Выключить `default`**: новый ACL-файл и `ACL LOAD`.
Откат: вернуть прежний ACL-файл (с `default`) и `ACL LOAD`; настройки клиентов откатываются тем же `up.sh`. Данные Redis не трогаются.

Единственное прерывание — рестарт на шаге 2 и пересоздание google-auth (секунды); токены в AOF сохраняются, пользователи остаются залогиненными.

### D7. Поведение при неверных учётных данных

Остаётся как есть: google-auth на старте завершается с ошибкой и без значения пароля в журнале (сообщение берётся из ответа Redis `WRONGPASS`, пароль в нём не повторяется — проверить в задаче 2.2). Деградация без хранилища токенов недопустима: сервис принимал бы входы, которые нельзя отозвать.

### D8. Операторский доступ и скрипты

`docker exec -it wallet-<env>-redis-1 redis-cli --user admin` с паролем из `admin.env` (через `REDISCLI_AUTH`, не в аргументах). `test-refresh.sh` берёт `admin.env` и выполняет `FLUSHALL` под `admin`. README (корневой, `infra/env`, `infra/db`) показывает подключение с аутентификацией.

## Risks / Trade-offs

- **ACL не покрыл команду или префикс** → штатная функция даёт ошибку (отзыв всех токенов админом, счётчики входа). → Сверка с клиентом и `SCAN` на prod/test (1.1), прогон всех сценариев на test с проверкой `ACL LOG` (5.3–5.4), правка ACL до prod.
- **Нет переподключения у google-auth** (существующая хрупкость): любой рестарт Redis ломает сервис до пересоздания. → Выкат учитывает это (D6), отдельная задача на переподключение — вне объёма.
- **Выключение `default` при живом клиенте** → простой. → Шаг 4 D6: проверка `CLIENT LIST`, откат `ACL LOAD`.
- **Пароль в сети без TLS** остаётся в открытом виде при `AUTH`. → TLS в `add-internal-mtls`, группа 9; до этого защита от неаутентифицированного доступа, но не от перехвата.
- **Потеря секретов** (удалён `redis/`) → скрипт сгенерирует новые, а ACL-файл и сервисы обновятся при следующем `up.sh`; токены в Redis не затрагиваются, потому что хранятся отдельно от паролей.
- **Генерируемый каталог с ACL** читается всеми (0644), но содержит только хеши. → Хеши SHA-256 от 256-битных паролей не подбираются; пароли случайные, не человеческие.
- **Jenkins** (BuildPlatform, вне git) может вызывать `redis-cli` без пароля. → Проверка в 1.3, правки с резервной копией (каталог jobs не под git).

## Migration Plan

Порядок — D6, шаги соответствуют группам в `tasks.md`: подготовка → google-auth → скрипты и compose → мониторинг → включение на test (шаги 2–5) → откат на test → prod. Prod — только после полного прогона на test, в тихое время (рестарт Redis и пересоздание google-auth на секунды). После выкатки `add-internal-mtls`, задача 1.2, считается выполненной.

## Open Questions

- Точный список команд для `exporter` (зависит от версии redis_exporter v1.62.0 и включённых проверок ключей): уточняется на test по `ACL LOG`, на спеку не влияет.
