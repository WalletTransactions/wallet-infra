# Design

## Context

Контур — compose-проект `wallet-<env>`; `compose.yaml` один на prod и test, различия задают
`infra/env/<env>.env`, `tags.env` и секреты (`db.env`). Сейчас `db` — `postgres:16-alpine`,
почти все переменные в `compose.yaml` объявлены как `${VAR:?}`. Поэтому новая обязательная
переменная ломает любой контур, где её нет. `init-db.sh` прогоняется при пустом томе или
из `migrate.sh`, если нужной базы нет; он идемпотентен. Миграции баз сервисов берутся из
образа сервиса. `backup.sh` и `test-refresh.sh` работают с четырьмя базами. Мотивация — в
proposal.md.

## Goals / Non-Goals

**Goals:**
- Postgres контура получает `vector`; под `wallet-docs` — своя база и роль только с DML.
- Контур без docs (без секретов, профиля и тега) поднимается и выкатывается как сейчас.
- Выкат `wallet-docs` — тем же `deploy.sh`, миграции из образа сервиса.

**Non-Goals:**
- Сам сервис `wallet-docs`, схема `doc_chunks`, размерность эмбеддингов, ANN-индекс.
- Маршрут `/api/docs/*` в гейтвее, Jenkins-заливка индекса, разделы в клиентах.
- Бэкап индекса: он воспроизводим.

## Decisions

**D1. Образ `pgvector/pgvector:pg16`, а не свой.** Меняется одна строка в `compose.yaml`;
версия Postgres остаётся 16, `pg_stat_statements` входит в contrib этого образа. Свой образ
дал бы только отсутствие смены базового дистрибутива, но потребовал бы сборки и поддержки
образа в ghcr. Альтернатива «отдельный инстанс Postgres только под docs» отвергнута: лишние
~400 МБ RAM на машине с 14 ГБ и ещё один том.

**D2. Смена образа = пересоздание тома.** Alpine (musl) и Debian (glibc) по-разному
сортируют строки, поэтому индексы старого тома после смены образа недостоверны. Данные
можно пересоздавать (решение владельца), но для prod порядок такой: `backup.sh prod` →
`down` → удалить том `db-data` → `up.sh` → `pg_restore` дампов (логический формат
переносится между libc). Для test данные берутся из `test-refresh.sh`. Альтернатива
«оставить том и просто заменить образ» отвергнута из-за риска тихой порчи индексов.

**D3. Опциональность через `${VAR-}`, а не `${VAR:?}`.** Для `DOCS_POSTGRES_*`,
`WALLET_DOCS_TAG` и `WALLET_DOCS_URL` используется пустое значение по умолчанию. Если
в `compose.yaml` оставить `:?`, интерполяция упала бы и для неактивного профиля.
Сервис `wallet-docs` получает `image: …:${WALLET_DOCS_TAG:-unset}`, чтобы описание
оставалось валидным без тега. Гейтвей получает `WALLET_DOCS_URL: ${WALLET_DOCS_URL-}`,
а значение задаётся в `<env>.env` только вместе с профилем (D4): без профиля адрес пуст и
гейтвей отвечает `404` по спеке `docs-route`, а не `502` на несуществующее имя. Это проверяется в задачах 2.2 и 2.3 на живом compose.

**D4. Включение профиля — `COMPOSE_PROFILES=docs` и `WALLET_DOCS_URL=http://wallet-docs:8089` в `<env>.env`.** Модуль включается и выключается двумя строками одного файла. `env_compose` уже
передаёт `<env>.env` как `--env-file`, поэтому `lib.sh` не нужно менять. Включается в
test, затем в prod. Альтернатива «флаг `--profile` в `up.sh`» отвергнута: тогда выкат
через `deploy.sh` и ручной `docker compose` расходились бы в том, что запущено.

**D5. Блок docs в `init-db.sh` условный.** Условие — непустые `DOCS_POSTGRES_USER`,
`_PASSWORD`, `_DB`. Без них блок пропускается целиком, включая `GRANT CONNECT` для
`monitoring`. С ними: роль, база, `REVOKE CONNECT … FROM PUBLIC`, `GRANT CONNECT` своей
роли и `monitoring`, затем `CREATE EXTENSION vector` и `pg_stat_statements` в базе docs
(иначе `postgres-exporter` пишет ERROR на каждый опрос, как было с perf) и
`ALTER DEFAULT PRIVILEGES` для DML. `dumper` `CONNECT` не получает: индекс не бэкапится.
`CREATE EXTENSION vector` выполняет сам `init-db.sh` (его запускает `migrate.sh` под
суперпользователем), а роль сервиса — нет; миграции сервиса не создают расширение, они только используют его типы.

**D6. База docs в `up.sh` и `migrate.sh` — по условию.** В `migrate.sh` добавляется
база `docs` (сервис `wallet-docs`, образ из `tags.env`). В `up.sh` шаг выполняется,
если профиль `docs` включён, `DOCS_POSTGRES_DB` задан и тег есть. Иначе пропускается.
`backup.sh` и `test-refresh.sh` список баз не меняют. Это держит инвариант: нет docs —
скрипты ведут себя как раньше.

**D7. Гейтвей получает `WALLET_DOCS_URL` без `depends_on`.** Тот же приём, что у
`wallet-mcp`: гейтвей ходит к апстриму на каждый запрос, упавший docs даёт 502, остальной
стенд работает. Адрес непуст только при включённом профиле (D3, D4): профиль выключен —
`404 gateway: docs не подключён`. Гейтвей без маршрута лишнюю переменную игнорирует, так что порядок
выкатки репозиториев не важен.

**D8. Порт и ресурсы.** `wallet-docs` слушает 8089 (8088 — wallet-mcp, 8090 — гейтвей),
`mem_limit: 128m` как стартовое значение (эмбеддинги считает LM Studio на хосте; сервис
только держит соединения и ходит в Postgres). Порты на хост не публикуются. `wallet-docs`
добавляется в `WALLET_SERVICE_PORT` в `lib.sh`, чтобы smoke `deploy.sh` проверял `/version`.

## Risks / Trade-offs

- [Потеря данных prod при пересоздании тома] → `backup.sh prod` с меткой `pre-pgvector`
  перед заменой и проверка дампа `pg_restore -l`; окно простоя согласуется до начала.
- [`${VAR:?}` на неактивном профиле всё же упадёт] → D3 и задача 2.3: проверка
  `docker compose config` с профилем и без, на обоих контурах.
- [Образ pgvector больше alpine, +~50 МБ] → диск на `/` ограничен, перед сменой убедиться
  в свободном месте и удалить старый образ после проверки.
- [RAM `db` 384 МБ] → индекс по тысячам чанков мал; если вырастет, поднять лимит
  отдельным change после измерения.
- [`init-db.sh` ранее не знал условных блоков] → блок короткий и повторяет остальные;
  идемпотентность проверяется вторым запуском (задача 3.2).
- [Расхождение версий `pg_dump`] → дамп снимает `dumper` внутри контейнера `db` того же
  образа; перед заменой сверить `postgres --version` старого и нового.

## Migration Plan

1. test: включить профиль не сразу — сначала сменить образ и пересоздать том (`down`,
   удалить том, `up.sh test`, `test-refresh.sh`), убедиться, что всё здорово.
2. test: добавить `DOCS_POSTGRES_*` в `db.env`, прогнать `init-db.sh` через `migrate.sh`
   (база появляется, расширение есть), без включения профиля.
3. prod: окно простоя, `backup.sh prod --label pre-pgvector`, замена образа и тома,
   восстановление дампов, `up.sh prod`.
4. Включение профиля `docs` в test/prod (`COMPOSE_PROFILES` и `WALLET_DOCS_URL` в `<env>.env`) — после появления образа `wallet-docs` в ghcr.
5. Откат: вернуть образ `postgres:16-alpine`, пересоздать том и восстановить из дампов
   `pre-pgvector`. Секреты `DOCS_*` можно оставить: без профиля они ничего не включают.

## Open Questions

- Нужна ли `wallet-docs` отдельная роль только для чтения индекса (как `perf_reader`),
  например для ручной отладки. Не влияет на спеки; решается вместе с сервисом.
