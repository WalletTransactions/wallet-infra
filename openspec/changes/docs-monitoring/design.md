# Design

## Context

Prometheus сидит в сетях обоих контуров и опрашивает сервисы по alias `<сервис>-<env>`
(design D11 `add-prod-test-environments`). У `wallet-docs` alias `wallet-docs-${WALLET_ENV}` и
порт 8089 уже есть в `compose.yaml`; не хватает только job в `prometheus.yml` и строки на
дашборде. Сервис необязательный (профиль `docs`).

## Decisions

**D1. Один job `wallet-docs`, обе цели всегда перечислены.** Как у остальных сервисов: цель
выключенного контура — `down`. Условное включение целей в статическом конфиге потребовало
бы генерации файла; `down` для необязательного модуля — штатное состояние, панель `up`
показывает его явно, алертов в стенде нет.

**D2. Доля отказов — через счётчик `docs_refusals_total`, а не по тексту ответа.** Счётчик
добавляет wallet-docs (change `docs-answer-quality`): исход `answered` не отличает отказ
(«этого нет») от ответа. Панель `rate(docs_refusals_total) / rate(docs_answers_total{result=
"answered"})` пуста до выката счётчика — это отмечено в описании панели.

**D3. Панели строки — по образцу `wallet-mcp`.** RPS по `result`, доля отказов, отклонённые
токены, заливки индекса, p95 `/api/docs/ask` (гистограмма `http_request_duration_seconds` с
фильтром пути), `up`, RSS контейнера (cAdvisor, имя `wallet-<env>-wallet-docs-1`).
Переменная `$env` фильтрует контур, как у остальных строк.

## Risks / Trade-offs

- **Пустая панель отказов до выката wallet-docs.** Приемлемо и описано; порядок выката —
  сначала wallet-docs (счётчик), затем перезапуск мониторинга.
- **Метка пути в `http_request_duration_seconds`.** Если путь не вынесен в метку, p95 `/ask`
  выбирается по `handler`/`path` существующей метки; проверяется на живых данных test.
