# docs-index-upload Specification

## Purpose
Как индекс документации наполняется на стенде: скрипт контура собирает спеки репозиториев и заливает их в wallet-docs, Jenkins запускает его вручную и по расписанию. Без wallet-docs заливка пропускается без ошибок.

## Requirements

### Requirement: Скрипт заливки
`infra/env/docs-index.sh <prod|test> <репозиторий|all>` SHALL для каждого указанного репозитория собрать все файлы `*.md` из его каталога `openspec/` и файлы `README.md` (см. «README в заливке») в рабочей папке организации на хосте, отправить их `PUT /docs/index/{репозиторий}` в запущенный контейнер `wallet-docs` контура и напечатать одну строку итога `<репозиторий>: chunks=<n> embedded=<n> reused=<n> skipped=<n>`. Значение `all` SHALL означать все каталоги организации, в которых есть `openspec/`.

#### Scenario: Один репозиторий
- **WHEN** выполняется `docs-index.sh test wallet-gateway` при запущенном `wallet-docs`
- **THEN** выводится строка с `chunks` больше нуля, код выхода 0

#### Scenario: Все репозитории
- **WHEN** выполняется `docs-index.sh test all`
- **THEN** итоговая строка выводится для каждого репозитория с `openspec/`, а репозитории без `openspec/` пропускаются с пометкой

#### Scenario: Только спеки
- **WHEN** репозиторий содержит `openspec/**/*.md`, `README.md`, исходный код и `.env`
- **THEN** в запрос попадают только `*.md` из `openspec/` и файлы `README.md`, остальное не читается и не отправляется

### Requirement: Токен не покидает контейнер
Скрипт SHALL выполнять запрос внутри контейнера `wallet-docs` (`docker exec -i`), где заголовок `X-Index-Token` берётся из окружения контейнера. Значение `INDEX_TOKEN` SHALL NOT появляться в аргументах процессов хоста, в выводе скрипта, в журнале Jenkins и в файлах рабочей папки.

#### Scenario: Список процессов
- **WHEN** во время заливки просматривается список процессов хоста
- **THEN** значения токена в командных строках нет

#### Scenario: Вывод и журнал
- **WHEN** заливка завершилась с ошибкой `401`
- **THEN** вывод и журнал Jenkins содержат статус и причину, но не токен

### Requirement: Мягкий отказ без wallet-docs
Если профиль `docs` в контуре выключен, контейнер `wallet-docs` не запущен или запрос завершился ошибкой, скрипт SHALL написать предупреждение `docs-index: <причина>` и завершиться кодом 0, а при `all` — продолжить с остальными репозиториями. С флагом `--strict` скрипт SHALL вернуть ненулевой код. Контур при этом SHALL NOT изменяться.

#### Scenario: Профиль выключен
- **WHEN** `docs-index.sh test all` запускается на контуре без `wallet-docs`
- **THEN** выводится одно предупреждение, код выхода 0, сети, контейнеры и теги не изменились

#### Scenario: Строгий режим
- **WHEN** тот же запуск с `--strict`
- **THEN** код выхода ненулевой

#### Scenario: Один репозиторий не залился
- **WHEN** при `all` заливка репозитория отвечает `500`
- **THEN** остальные репозитории всё равно заливаются, в конце печатается список неудачных, код 0 (без `--strict`)

### Requirement: Блокировка контура и права
Скрипт SHALL брать блокировку контура (`env_lock`), как остальные скрипты, чтобы заливка не шла одновременно с выкатом или миграциями. Он SHALL быть доступен для запуска через `env_run.sh` (имя вида `docs-index.sh`).

#### Scenario: Выкат идёт одновременно
- **WHEN** во время `deploy.sh test …` запускается `docs-index.sh test all`
- **THEN** заливка ждёт окончания выката и затем выполняется

### Requirement: Jenkins-job
Job `docs-index` SHALL запускать скрипт через `env_run.sh` с параметрами `ENV` (`test`/`prod`, по умолчанию `test`) и `REPO` (`all` по умолчанию), по ручному запуску и ежесуточно ночью, без параллельных сборок. Если скрипт сообщил предупреждение «docs-index: …», сборка SHALL получать статус `UNSTABLE`, а не `FAILURE`.

#### Scenario: Ручной запуск
- **WHEN** оператор запускает job с `ENV=test`, `REPO=wallet-gateway`
- **THEN** выполняется заливка одного репозитория, сборка `SUCCESS`

#### Scenario: Сервис не подключён
- **WHEN** job запускается на контуре без `wallet-docs`
- **THEN** сборка завершается `UNSTABLE` с предупреждением в журнале и не мешает другим job'ам

### Requirement: README в заливке
Скрипт SHALL добавлять в тело заливки файлы с именем ровно `README.md` на любой глубине репозитория, кроме каталогов `third_party/`, `node_modules/`, `.worktrees/`, `build/`, `vendor/`, `.git/` и `openspec/`. Симлинки SHALL NOT читаться. Пути в теле SHALL быть относительными к корню репозитория.

#### Scenario: Корневой и вложенный README
- **WHEN** в репозитории есть `README.md` и `infra/env/README.md`
- **THEN** оба файла попадают в запрос с путями `README.md` и `infra/env/README.md`

#### Scenario: README вендорной библиотеки
- **WHEN** в репозитории есть `third_party/wallet-common/README.md`
- **THEN** файл в запрос не попадает

#### Scenario: Репозиторий без openspec
- **WHEN** выполняется `docs-index.sh test all`, а в каталоге организации есть репозиторий только с `README.md` и без `openspec/`
- **THEN** он пропускается с пометкой, как раньше

### Requirement: Заливка при включённом mTLS
Если в контейнере `wallet-docs` заданы `TLS_CERT`, `TLS_KEY` и `TLS_CA`, скрипт SHALL выполнять запрос по `https://wallet-docs:8089` с сертификатом самого контейнера, проверяя сертификат сервера по `TLS_CA` и имя по SAN. Иначе запрос SHALL идти по `http://127.0.0.1:8089`. Токен и пути сертификатов SHALL NOT попадать в аргументы процессов хоста, вывод и журнал Jenkins.

#### Scenario: Контур с mTLS
- **WHEN** `docs-index.sh test wallet-infra` выполняется на контуре с `INTERNAL_MTLS=true`
- **THEN** заливка проходит, выводится строка итога с `chunks` больше нуля

#### Scenario: Контур без mTLS
- **WHEN** `docs-index.sh prod all` выполняется на контуре без mTLS
- **THEN** запрос идёт по `http://127.0.0.1:8089`, поведение как раньше

#### Scenario: Сертификат не читается
- **WHEN** файл из `TLS_CERT` в контейнере отсутствует или не читается
- **THEN** скрипт пишет `docs-index: <репозиторий>: сертификат контейнера не читается`, продолжает с остальными, код 0 без `--strict`

### Requirement: Причина отказа в сообщении
Строка предупреждения `docs-index: …` SHALL называть причину отказа запроса, а не только код `000`: сертификат не читается, TLS-рукопожатие не прошло, сервис недоступен (соединение не установлено или оборвано) либо сервис ответил кодом.

#### Scenario: Рукопожатие не прошло
- **WHEN** контейнер предъявляет сертификат, не принятый сервером
- **THEN** предупреждение содержит «TLS-рукопожатие не прошло», а не «000»

#### Scenario: Сервис не отвечает
- **WHEN** запрос завершается без ответа (обрыв, таймаут)
- **THEN** предупреждение содержит «сервис недоступен» и код `curl`

#### Scenario: Отказ с кодом
- **WHEN** wallet-docs отвечает `401`
- **THEN** предупреждение содержит `wallet-docs ответил 401` и `error` из тела, но не токен
