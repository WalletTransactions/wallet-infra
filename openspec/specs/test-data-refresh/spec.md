# test-data-refresh Specification

## Purpose
Определяет, какими данными наполнен контур test: исходный сид при создании и ручная перезаливка из дампа prod с обязательной вычисткой того, что принадлежит только prod (сессии, привязки и состояние prod-бота).

## Requirements

### Requirement: Исходное наполнение test
Новый (пустой) контур test SHALL после первого выката иметь накаченные схемы всех баз (auth, wallet, telegram, ai) и сид. Сид содержит роли и учётку администратора из `ADMIN_EMAILS` test. Реальных данных prod в test в этот момент SHALL NOT быть.

#### Scenario: Свежий test
- **WHEN** контур test развёрнут на пустых томах
- **THEN** администратор может войти через `:8091`, у него нет ни одного кошелька, и в базах нет данных prod

### Requirement: Перезаливка test из prod
SHALL быть ручная операция, которая заменяет данные всех баз test данными из свежего дампа prod. Схема test после этого соответствует версиям миграций сервисов, выкатанных в test.

#### Scenario: Успешная перезаливка
- **WHEN** запускается перезаливка test
- **THEN** кошельки и операции пользователей в test совпадают с prod на момент дампа, а миграции test, которых ещё нет в prod, накачены поверх

#### Scenario: Prod не затронут
- **WHEN** выполняется перезаливка test
- **THEN** в prod не выполняется ни одной записи, а дамп снимается с правами только на чтение

### Requirement: Вычистка после перезаливки
После перезаливки в test SHALL NOT оставаться состояния, привязанного к prod. Redis test SHALL очищаться полностью, то есть все сессии и refresh-токены сбрасываются. Привязки Telegram (`telegram_links` в auth, `tg_link` в telegram) и offset getUpdates prod-бота (`tg_update_offset`) SHALL удаляться.

#### Scenario: Сессии сброшены
- **WHEN** перезаливка завершилась
- **THEN** ни один refresh-токен, выданный до перезаливки, не обменивается, и ручки google-auth test отвечают `401` на прежние access-токены

#### Scenario: Access-токен до exp
- **WHEN** после перезаливки на `/api/*` гейтвея test приходит access-токен, выданный до неё
- **THEN** гейтвей принимает его до `exp` (не дольше `ACCESS_TOKEN_TTL_SECS`, 15 минут): он проверяет токен по JWKS и в Redis не смотрит (google-auth, design D4)

#### Scenario: Привязки бота сброшены
- **WHEN** перезаливка завершилась
- **THEN** таблицы `telegram_links`, `tg_link` и `tg_update_offset` в test пусты, и test-бот на любые команды отвечает предложением привязать аккаунт

### Requirement: Перезаливка не идёт поверх выката
Перезаливка test SHALL брать ту же блокировку контура, что и выкат. Пока идёт перезаливка, сервисы test, которые пишут в БД, SHALL быть остановлены.

#### Scenario: Тег во время перезаливки
- **WHEN** во время перезаливки test появляется новый rc-тег
- **THEN** выкат этого тега в test начинается только после окончания перезаливки
